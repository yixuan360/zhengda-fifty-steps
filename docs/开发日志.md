## 一、技术方案演进

### 1.0 起点：react-native-maps + 高德瓦片 + expo-location

- **地图**：`react-native-maps` 渲染 Google Maps SDK 底图，叠加高德瓦片 URL 覆盖为国内图源。
- **定位**：`expo-location` 获取 WGS-84 坐标，通过 `coordtransform` 算法转为 GCJ-02。
- **音频**：`react-native-track-player` v4.1.2 后台播放 + 锁屏控制。
- **构建**：EAS Build（Expo CNG），`android/` 目录不入库。

**暴露的问题**：
- `react-native-maps` 依赖 Google Maps SDK，国产无 GMS 手机底图空白/初始化崩溃；
- RN `SurfaceView` 渲染导致悬浮播放条被遮挡（z-order 问题）；
- WGS-84 → GCJ-02 双重转换链路增加了偏差风险。

### 1.1 高德原生全家桶（→ V4）

**决策**：整体替换为高德原生双 SDK。

| 模块 | 旧方案 | 新方案 |
|------|--------|--------|
| 地图 | react-native-maps + UrlTile | `react-native-amap3d`（高德 3D SDK 9.6.0） |
| 定位 | expo-location + WGS-84→GCJ-02 | `react-native-amap-geolocation`（定位 SDK 6.2.0，GCJ-02 直出） |
| 渲染 | SurfaceView（z-order 问题） | **TextureMapView**（根治图层遮挡） |
| 坐标转换 | coordtransform 双向链路 | **已删除**（高德 SDK 直出 GCJ-02） |

**收益**：无 GMS 依赖、坐标系天然统一、图层遮挡根治、定位精度更高（`Hight_Accuracy` 模式）。

### 1.2 静态底图方案（→ V5.1~V5.3，已归档）

在 V4 稳定运行后，进一步探索了完全去掉原生地图 SDK 的"静态底图 + 坐标映射"方案：

- 用校园平面图 JPEG + 线性插值（后升级为多点最小二乘仿射变换）将 GCJ-02 映射到底图像素；
- 手势交互用 `react-native-gesture-handler` + JS 驱动 Animated；
- 定位改用 `expo-location` + `coordtransform` 转 GCJ-02。

**最终结论**：静态底图方案在手势交互、设计系统、仿射标定方面成果丰硕，但**地图体验不如高德原生底图直观和流畅**（无法无限缩放、无 3D 建筑、POI 缺失）。该方案完整代码已归档于 Git 标签 `v5.3-static-map`，设计系统和手势工具函数部分被复用。

### 1.3 玻璃拟态视觉美化（→ V5.4）

在 V4 高德原生方案基础上，应用"轻玻璃拟态 + 自然色系"设计系统：

- **设计语言**：半透明白底卡片（`rgba(255,255,255,0.88)`）+ 16px 大圆角 + 柔和阴影；
- **主色**：郑大校徽青绿 `#1A7A5A`，点缀赭石 `#C67B4B`；
- **底色**：晨曦灰 `#F2F4F6`（户外不刺眼）；
- **改造范围**：SpotCard / list.tsx / 详情页 / Tab 栏 / AudioBar 进度条 / map.tsx 状态提示条。

## 二、关键问题与解决方案

### P0-1：EAS 构建报错 — RNTP Kotlin 编译失败

**现象**：`react-native-track-player:compileReleaseKotlin FAILED`，报 `Bundle?` 空安全类型不匹配。

**根因**：Expo SDK 57 自带的新版 Kotlin 编译器对可空类型更严格，RNTP 4.1.2 的 `MusicModule.kt` 两处将 `Bundle?` 传给了非空参数。

**方案**：`patch-package` 本地补丁（`patches/react-native-track-player+4.1.2.patch`），两处改为 `?.let { Arguments.fromBundle(it) }`。补丁随 `postinstall` 钩子在 EAS 云端自动重放。

### P0-2：高德 SDK Duplicate class 构建失败

**现象**：`com.amap.api:3dmap:9.x` 内置定位核心类，与 `com.amap.api:location:6.2.0` 类冲突。

**方案**：全局排除独立 location 包。EAS 路径用 `plugins/withExcludeAmapLocation.js` 注入 Gradle 配置；本地路径在 `app/build.gradle` 末尾加同款 `configurations.all { exclude }`。

### P0-3：RNTP 新架构运行时崩溃（3 类）

**现象 1**：`TurboModuleInteropUtils$ParsingException: Unable to parse @ReactMethod annotations`。

**根因**：RN 0.86 强制 Bridgeless 新架构，互操作层校验要求所有 `@ReactMethod` 返回 void。RNTP 4.1.2 有 37 个方法用表达式体 `= scope.launch {}`（隐式返回 `Job`）——其中 1 个跨行声明极易被漏掉。

**方案**：37 个方法全部转 void 块体 `{ scope.launch {...} }`（含跨行声明补漏），统一并入 `patches/` 中。

**现象 2**：`RuntimeException: You should not use ReactNativeHost directly in the New Architecture`。

**根因**：`MusicService.emit` 调用旧架构 `reactNativeHost` API，Bridgeless 下直接 throw。

**方案**：`MusicService.kt` 的 `emit`/`emitList` 两处改为 `(application as? ReactApplication)?.reactHost?.currentReactContext`。

**现象 3**：`newArchEnabled: false` 无法关闭新架构。

**结论**：RN 0.86 已移除旧架构运行时，该开关静默失效。兼容性问题一律在库层面解决，不再尝试关闭新架构。

### P0-4：`localhost` 烧包导致真机无法同步数据

**现象**：App 内景点数据始终为空，地图/列表空白。

**根因**：`EXPO_PUBLIC_API_BASE_URL=http://localhost:8000` 在构建时烧入 APK，手机上 `localhost` 指向手机自身而非后端服务器。

**方案**：多路径保障。
- 开发/测试：改为电脑局域网 IP（`192.168.0.107`），同时需在 `server/.env` 的 `ALLOWED_HOSTS` 中加入此 IP、Windows 防火墙放行 8000 端口；
- 生产：改为公网 HTTPS 域名，且移除 `usesCleartextTraffic`；
- 调试捷径：`adb reverse tcp:8000 tcp:8000` 临时隧道免打包。

### P1-1：地图页无法下拉刷新（空列表死锁）

**现象**：无数据时列表页连下拉刷新入口都看不到。

**根因**：空状态用独立 `<View>` 渲染在 FlatList 外面，`RefreshControl` 随之消失。

**方案**：空状态改用 `ListEmptyComponent` 内嵌到 FlatList 内部，`RefreshControl` 永久在位。

### P1-2：离线首启无数据

**现象**：首次启动且无网络时，地图和列表完全空白。

**方案**：新增离线兜底逻辑。`constants/seedSpots.ts` 内置 42 个景点数据（与服务器数据库同步），启动时调用 `seedIfEmpty()`：SQLite 为空则灌入、网络通了被服务器数据整体覆盖。

### P1-3：定位精度提示误报

**现象**：GPS 逐秒波动导致"精度不足"横幅疯狂闪烁。

**方案**：三项优化。
- 阈值从 20m 放宽到 30m（兼容 Wi-Fi 混合定位的 25~30m 区间）；
- 滞回消抖：连续 3 个坏样本才判不合格（防止闪烁），1 个好样本立即恢复（保证响应快）；
- 横幅显示实测精度数值（如 `34m（需≤30m）`），让用户看到距离门槛差多少、自己走到室外。

### P2：CNG 双路径配置漂移

**教训**：EAS 云构建走 CNG prebuild（以 `app.config.ts + plugins/` 为真源），本机 `android/` 目录仅供 `expo run:android`。**任何原生配置（权限/Key/Proguard/类冲突排除）必须两边同步**，否则会出现"本地能跑、云构建闪退/白屏"的经典 Bug。

## 三、依赖与构建总结

| 类别 | 最终依赖 | 说明 |
|------|---------|------|
| 地图 | react-native-amap3d 3.2.4 | 高德 3D SDK |

| 本地库 | expo-sqlite 57.x | SQLite 三表、无 Migration 框架 |
| 网络 | axios 1.x | 统一拦截器 |
| 构建 | EAS Build（CNG） | android/ 不入库；app.config.ts + plugins/ 为真源 |
| 已移除 | react-native-maps / expo-location / reanimated / worklets | 冗余或已替换 |
