## 四、数据架构与数据库设计

### 4.1 同步机制
App 启动或下拉刷新时，GET 请求拉取全部景点数据（<100条，约1MB），在 SQLite 单事务内执行 `DELETE 旧数据 → INSERT 新数据`。同步失败则沿用本地数据。

### 4.2 服务端 MySQL 表结构
```sql
-- 景点表（单表设计，不拆子表）
CREATE TABLE spots (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  name            VARCHAR(100) NOT NULL,
  lat             DOUBLE NOT NULL,
  lng             DOUBLE NOT NULL,
  trigger_radius  INT DEFAULT 50,
  summary         TEXT,
  description     TEXT NOT NULL,
  image_url       VARCHAR(500),              -- 景点图片 URL
  audio_url       VARCHAR(500),              -- 音频 URL
  is_active       TINYINT(1) DEFAULT 1,
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 全局配置表
CREATE TABLE global_config (
  `key`         VARCHAR(100) PRIMARY KEY,
  `value`       JSON NOT NULL,
  updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.3 客户端 SQLite 表结构
```sql
CREATE TABLE spots (
  id              INTEGER PRIMARY KEY,
  name            TEXT NOT NULL,
  lat             REAL NOT NULL,
  lng             REAL NOT NULL,
  trigger_radius  INTEGER DEFAULT 50,
  summary         TEXT,
  description     TEXT NOT NULL,
  image_url       TEXT,
  audio_url       TEXT,
  is_active       INTEGER DEFAULT 1,
  updated_at      INTEGER
);

CREATE TABLE play_history (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  spot_id   INTEGER NOT NULL,
  played_at INTEGER NOT NULL
);
```
*注：App 启动时检测表是否存在，不存在则建表；V1 无需引入 Migration 框架。*

## 五、核心业务设计：导览引擎 (useTour)

全部触发逻辑集中在一个 `useTour.ts` 文件中：

1. **订阅位置**：throttle 1次/s 获取 GPS 定位（底层统一转 GCJ-02 坐标系）。
2. **精度过滤**：accuracy > 20m 暂停触发，防止漂移。
3. **距离计算**：accuracy ≤ 20m 时，Haversine 计算与所有 active 景点距离。
4. **滞回触发**：距离 ≤ 50m 触发播放，离开 > 70m 确认，20m 缓冲带防 GPS 抖动。
5. **冲突处理**：同时命中多景点按距离最近优先，其余加入内存队列顺位播放。
6. **冷却机制**：播放完成后该景点独立冷却 60s，写入本地 `play_history`，离开区域后自动重置。

## 七、文件处理与缓存策略

1. **上传与存储**：管理员通过 Django Admin 上传图片/音频至 `MEDIA_ROOT/`，开发阶段直接由 Django 提供静态文件服务。
2. **按需下载**：App 获取 URL 后，首次播放或浏览时下载，后续复用本地文件。
3. **极简缓存**：设置总缓存目录上限 **500MB**，超出直接清空整个缓存目录，内置兜底音频不清除。不做 LRU 分池等复杂策略。
4. **容错机制**：下载失败显示占位图，下次进入重新触发下载，不做重试队列。

## 八、核心风险与应对

| 优先级 | 风险点 | 应对方案 |
|--------|--------|----------|
| P0 | **地图视图层级遮挡**：RN SurfaceView 遮挡悬浮组件 | 验证 `androidZIndex`；失败切 `react-native-amap3d` |
| P0 | **坐标系不统一**：WGS-84 vs GCJ-02 偏差 | 定位底层强制转 GCJ-02；服务端录入即 GCJ-02 |
| P0 | **音频后台被杀**：Android 8.0+ 前台服务要求 | 配置 RNTP 通知渠道，验证锁屏连续播放 |
| P1 | **定位精度不足**：Android 12+ 模糊位置 | 引导精确位置授权；accuracy 过大暂停触发 |
