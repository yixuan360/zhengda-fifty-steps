## 一、项目一句话

在已上线的校园语音导览 App「郑大五十步」（Expo RN + Django，105 个景点 GPS 自动触发播报）之上，为郑州大学首届 AI 智能体大赛（方向：AI+校园服务与治理）开发**AI 驱动的校园叙事引擎**，作品名「郑大五十步·文脉」。

**定位定义（已定稿）**：文脉 = 校园的自然山水 + 建筑肌理 + 学科人文 + 校史城史的总和，以"五十步一景"的空间顺序被重新组织和讲述。AI 驱动的校园叙事引擎——用户到达景点听到自动播报（固定语音）；想深入了解某方面时，一键获得更专业、更全面的解读。

## 三、当前问题（M4 实测暴露，用户四条批评，全部成立）

1. **深度内容是复读机**：L2 输出"我们现在来到钟楼前，大家可以先抬头看看……"+ 卡片原文复述，比页面上方现有详细介绍还薄
2. **导游腔过重**：Prompt 为通过引用相似度校验，诱导出"我们现在来到"类现场引导词
3. **维度分类错误**：如钟楼"56米"被分到校史（history），应为建筑（architecture）
4. **交互繁琐**：逐级点击多层深度没有必要；用户要的是"点一次就拿到该方面丰富专业的内容"

**根因（已分析清楚）**：事实卡片是从景点自己的 description（56–291 字）拆出来的，13 张卡片 ≈ 简介本身；受限生成从薄材料里检索重组，产出不可能比原材料多。外部补源实证失败（LLM 编造 URL）。纵轴是空心的。**约束加错了位置**：运行时过度受限（只允许重组已审卡片），而 LLM 的自由知识应释放在内容生产端、由人审把关。豆包类应用丰富 because 参数知识自由生成——我们要把"自由"挪到生产端。

另有一个 UI bug：fallback 提示条在内容已加载时仍显示（待修）。

## 四、方案建议（Kimi 提出，**未经负责人批准，待定**）

> 以下为针对第三节问题的候选解决方案，是建议而非决定。负责人批准后才会变成执行计划。原文见聊天记录或本文件附档。

### 建议的产品终局：两层体验

- **L0 到达即播**：V1 固定语音自动播报，不动
- **L1 一键深入**：选维度 → 点一次"深入解读" → 拿到 300–500 字（60–90 秒音频）专业解读，一次到位，去掉逐级点击和"当前深度 Lx"显示

### 建议的深度稿质量标准（跨领域依据，写 Prompt 时必须体现）

- 博物馆阐释学（Tilden）：信息≠阐释，每个事实要回答 "so what"，与游客经验建立连接；开头有钩子，结尾有余味
- 音频脚本结构：钩子 → 展开 → 收束，按听觉逻辑写，禁止导游腔引导词（显式 negative list："我们现在来到/大家抬头看/稍作停留"等）
- 风格：专业科普讲解词，**禁止新增已审材料之外的事实**

### 建议的智能体架构：三个循环（比赛胜负手）

1. **服务循环**（已有）：感知（景点/维度/已听历史）→ 检索已审知识 → 受限生成 → TTS
2. **追问循环**（建议新增）：用户可追问（"为什么是 56 米？"）→ Agent 在已审知识内检索作答带来源 → 覆盖不了则诚实说"暂未收录"并记入**知识缺口清单**（多轮、会话记忆、工具调用、校准）
3. **生长循环**（建议，核心卖点）：缺口清单 → 管线自动起草针对性补充内容 → 人审 → 发布 → 系统在使用中自生长。作品定位从"导览问答应用"升维为"**自生长的校园知识智能体**"
