## 一、项目概览

「郑大五十步」是一个校园导览 App——打开就是地图，走近景点自动播放语音介绍，不盯屏幕。

| 维度 | 说明 |
|------|------|
| 产品定位 | 听觉优先、到达即播 |
| 目标用户 | 郑州大学新生/访客/游客 |
| 交付形态 | Android APK + Django 后端 + Django Admin |
| 核心链路 | GPS 定位 → 50m 触发 → Haversine 距离 → 滞回确认 → RNTP 音频播放 → 60s 冷却 |

## 四、核心链路详解

```
1. App 冷启动
   → _layout.tsx mount
   → syncAll() → GET /api/v1/spots/ → SQLite DELETE + INSERT (事务)
   → GET /api/v1/config/ → SQLite 覆盖写入
   → 网络失败 → 静默跳过，沿用本地旧数据

2. 地图渲染
   → map.tsx 从 tourStore 取 spots
   → MapView + 高德 UrlTile → 显示矢量地图
   → 过滤 isActive=true 的景点 → Marker 渲染
   → GPS 蓝点：useUserLocation → watchPositionAsync(1次/s)
     → WGS-84 → GCJ-02 (coordinate.ts) → 写入 tourStore

3. 导览触发 (useTour ★ 核心，v4.0 §6.1)
   → 订阅 tourStore.userLocation 变化
   → accuracy ≤ 20m? → 否则暂停触发
   → 遍历 spots → haversineDistance(user, spot)
   → dist ≤ triggerRadius (50m) + 滞回未进入? → 命中
   → 是否在冷却中? → 跳过
   → 是否正在播放? → 入队列 + 弱提示 "发现新景点:xxx"
   → 空闲? → 播最近，其余入队列

4. 音频播放 (useAudioPlayer)
   → getPlayer().play(url, name, spotId)
   → 等待 playerReady promise
   → enforceCacheSpace() → 超 500MB 清空
   → 检查本地缓存 → 有则直接用 / 无则 downloadAsync
   → TrackPlayer.reset → add → play
   → 失败 → setError → AudioBar 红色错误条

5. 播放完成
   → audioStore.state → 'idle'
   → useTour.onPlaybackComplete(spotId, wasManualStop)
   → 主动关闭? → early return (不写历史不冷却不出队)
   → setCooldown(spotId, 60s)
   → insertPlayHistory (fire-and-forget to SQLite)
   → dequeue() → 有则 setTimeout 500ms → playSpot(next)
```

## 七、项目亮点

1. **导览引擎单文件设计**：`useTour.ts` 将位置监听→距离计算→滞回→触发→冷却→排队→播放→完成回调全部集中在一个 ~160 行的 Hook 中，逻辑清晰透明。

2. **滞回机制**：进入 ≤50m 触发、离开 >70m 确认、20m 缓冲带，有效防 GPS 抖动，在真机校园场景中验证通过。

3. **AudioBar 错误条 + 弱提示交互**：播放失败有红色条（4s 自消），新景点命中有点按切换，远比"自动播放下一个"的体验更好。

4. **全量同步极简实现**：`isSyncing` 标志位 + `skipped` 返回值 + SQLite 单事务 `DELETE→INSERT`，~50 行代码覆盖所有边界条件。

5. **代码审核驱动质量**：3 轮审核共发现并修复 2 个🔴严重 + 17 个🟡一般 + 18 个🟢建议，架构红线 0 违规。

## 八、已知限制

| # | 限制 | 影响 | V2 解决方案 |
|:--:|------|------|------------|
| 1 | 微信登录未真实对接 | 用户无法用微信号登录 | 申请微信开放平台 AppID，调用 code2Session |
| 2 | 无播放记录上报 | 无法统计热门景点/用户偏好 | 新增 `POST /api/v1/play-history/` 上报接口 |
| 3 | 无已逛/未逛标记 | 用户不知道去过哪些景点 | 客户端基于 play_history 做 UI 标记 |
| 4 | 景点 < 100 条时全量同步 OK | 景点 > 500 条时流量浪费 | V2 引入增量同步 |
| 5 | 音频 TTS 未集成 | 管理员需手动上传音频 | V2 接入 TTS API + 异步 Celery 任务 |
| 6 | 无步行路线导航 | 用户只能看距离不知怎么走 | V2 接入高德路径规划 API |
| 7 | Android only | iOS 用户无法使用 | EAS Build 加 iOS profile |
| 8 | 缓存目录整体清空 | 超限时全删不精细 | V2 按 LRU 逐文件清理 |
